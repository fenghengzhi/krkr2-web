# 038 — 对象终结、主异常与深层释放

兼容目标是 TJS2 的引用计数和显式失效语义。[原引擎调试文档](https://krkrz.github.io/krkr2doc/kr2doc/contents/Debug.html) 明确说明循环引用不会自动检测，应用可以用 `invalidate` 断开引用环；[类文档](https://krkrz.github.io/krkr2doc/tjs2doc/contents/class.html) 区分失效与删除，并未规定隐式终结的精确时间。此前进度文档把任意对象环的自动回收列为必需能力，这超出了参考行为；应验证原有引用/断环行为以及 Web 宿主资源的实际所有权，不能靠更换垃圾回收语义掩盖泄漏。

首轮 [诊断 34861822171](https://github.com/fenghengzhi/krkr2-web/actions/runs/34861822171) 复用已验证的执行预算构建，在独立子进程中检查源码/字节码、调试开关和两种后端。每个后端仅 4/32 通过：普通作用域退出正常；抛错终结器保留脚本上下文，闭包双引用释放在第一处错误后中断并触发 WASM abort，数组清理遗漏后续对象，构造错误被终结器异常覆盖。字典用例还误用了不存在的实例 `clear` 方法，修正为绑定到实例的 `Dictionary.clear`，并按字典缺失成员的 void 语义检查清空；该夹具错误与产品问题分别保留。

实现让 `Release` 在终结器失败时仍消费该次引用。对象若在终结器中被新所有者保留，则继续持有它；真正销毁时，基础对象释放剩余成员和原生实例，避免失败的 Finalize 遗留资源。闭包先分离两个指针，再尝试释放两份引用并保留第一处异常。数组/字典清理先预留引用列表，清空成员后完成全部释放；某一终结器失败不会跳过后续对象。

C++ 变体和作用域所有者的析构不能向 noexcept 容器外传播异常。它们把错误交给最内层清理作用域，在 VM 指令或执行返回边界报告；已有主异常时丢弃次要错误，避免用户 catch 后再出现同一清理错误。显式 `invalidate` 抛错仍保留原对象有效性，以允许按参考行为处理或重试；不能简单在任何 Finalize 入口就把对象标为无效。

引用计数导致的深层递归释放在 32 层后将最后一份引用转交给对象内的链表队列，不分配新的队列节点。最外层释放在返回前排空队列，避免纯 Array/Dictionary 长链绕过函数深度限制后耗尽原生栈。这改变深链中隐式终结的内部调度，不实现循环检测。队列长度、深度和累计入队量提供只读诊断，以验证长链确实经过该路径且最终没有待释放对象。

本轮实现与新增深链用例尚未验证。所有构建、测试和可执行探测只在 GitHub-hosted Actions 运行；此前完整基线与失败材料保留。宿主对象隐式资源回收、终结器重入/暂停/取消以及原生分配失败还须继续验证，完整非插件目标保持进行中。
