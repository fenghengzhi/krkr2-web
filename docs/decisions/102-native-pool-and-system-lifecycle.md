## 真正回收原生寄存器栈池

此前 `TJSVariantArrayStackCompactNow` 为空。本批按当前每个 tTJS 实例持有一个池的结构遍历注册池，释放已归还且全为 void 的整块寄存器；活动或挂起的寄存器地址不移动，不清理活动块尾部，不在整理中申请内存。

先完成每个 slot 的 Clear，再减少使用计数；Clear 即使终结器抛错也已发布 void，因此回收整块不会重新调用脚本。注册表与池元数据采用固定锁序，用户终结器与可能挂起的操作始终在锁外；析构先退出注册表。即时整理不提前消费延迟整理请求，活动帧随后归还时仍能释放最后的空闲块。

只读私有诊断记录已分配／在用块及槽位，验证真实回收量，而非仅检查“不崩溃”。托管原生 ASan＋UBSan 和 TSan 编译同一生产 `.inc`，覆盖分配失败、终结器重入／抛错、另一线程的挂起所有者和注册／销毁并发。真实 Asyncify／JSPI 的 source／bytecode 另验证寄存器内容、终结器和 Stop。任意并发执行同一个 VM 不在支持范围内。源合同、哈希和锁序审计见 `out/verification/variant-stack/102-audit.md`。

## 自动整理与无窗口启动

自动空闲整理采用固定 MainForm 的 50 ms WatchTimer 和 DWORD 时间差：没有连续调用且距上次空闲整理严格超过 4000 ms 才请求等级 5。普通输入、显式整理及失活不会重置这个基点。连续处理器的移除要等清理轮结束；非 selfupdate 的 Layer 转场也参与原生连续调用状态。

真实应用失活请求等级 10，在对应脚本回调之前执行；普通游戏窗口或页面控件的焦点变化不能伪造它。自动维护不依赖 `eventDisabled`，但会等待暂停／冻结后的安全恢复边界；模态内使用既有 TJS 继续执行路径，不从挂起的 host import 重入外部 VM。捕获原生整理方法，脚本覆盖公开 `System.doCompact` 不会替换系统维护。Stop 撤销时钟与待办。

浏览器页面隐藏不能证明操作系统最小化，本批没有制造最小化信号；显式等级 15 仍可用。当前 Web 主控制器默认可见，保留该产品行为。`exitOnNoWindowStartup` 按原版默认值和整数转换工作，仅在成功启动结束、没有注册 Window 且控制器不可见时终止；隐藏 Window 仍计入数量，后续 evaluate 不重复执行启动判断，启动错误不被自动退出覆盖。

旧调度夹具现在计入真实 watch，暂停、图形丢失、失败及 Stop 后仍严格归零。两个忽略 delay、只取首回调的旧假时钟改为按到期时刻派发所有任务，保留原 Timer／转场的精确时刻断言，没有按 50 ms 过滤任务或隐藏生产维护。
