# 118　原配置 JPEG 解码与托管构建修复

本批把游戏主图和灰度遮罩的 JPEG 加载接到独立 WASM 内核。适用范围是实际播放器和 headless Session 通过图像扩展名选中的 JPEG。第三方嵌入若只提供通用图像解码器，仍沿用其宿主实现。新实现和以下验收均待 GitHub-hosted Actions 执行。

## 游戏可观察的行为

固定参考为 KRKR2 `dec49af97e174d31059c3ccd7efc700ba3c6b788` 的 `TVPLoadJPEG`、启动参数处理和 libjpeg2 配置。源码来自 IJG 6b，归档 613,261 字节，SHA-256 为 `75c3ec241e9996504fe02a9ed4d12f16b74ade713972f3db9e65ce95cd27e35d`。构建逐文件核对源码，再使用原版的 `jconfig.h` 和 `jmorecfg.h`。后者指定 BGR 通道顺序和 16 位乘数。原头文件还声明了 MMX 接口，原 Borland 优化库及其浮点舍入尚无逐像素实测。编译配置、来源与文件哈希见 [源码清单](../../native/image-jpeg/source.json)。

普通加载采用库选择的输出色彩空间。RGB 输出按原加载器的 BGR 顺序解释并转换成引擎 RGBA。遇到 CMYK 等其他输出时，原加载器把每行的前 W 个分量字节逐个扩成灰度像素。独立遮罩请求原生 `JCS_GRAYSCALE`，YCbCr 图像直接取亮度分量。不支持的转换通过当前 VM 的 `TVPJPEGLoadError` 返回 IJG 数字错误码。省份图的调色板模式在打开解码器前返回原有错误。

引擎在启动时读取一次 `-jpegdec`。默认和 `normal` 使用 IFAST 与高质量色度上采样，`low` 关闭该上采样，`high` 使用浮点 IDCT。脚本随后可通过 `System.setArgument` 改变查询到的参数字符串，已经启动的解码器设置在该 Session 内固定。

嵌入可传 `PlayerOptions.jpegPrecision`，应用可用 `?jpegdec=low`、`normal` 或 `high` 启动。省略时 `System.getArgument("-jpegdec")` 返回 void，实际解码用 normal。应用将无法识别的 URL 值归一为 normal。Worker 初始化字段可选，会话协议为 42。

空输入在首读时产生原错误。非空输入在末尾缺少 EOI 时遵循原读取策略，记录警告并补入结束标记，完整的熵数据仍可能解码成功。头部、渐进扫描预读、每组扫描行和最终收尾分别推进。成功返回的行可在后续解码失败时保留在调用者的位图中。宿主 I/O、暂停、Stop、资源预算和解码器数值错误分别保留自身原因。

## 资源生命周期与范围

每个 Session 按需创建自己的内核。WASM 每次接收最多 8,192 字节，保留最多 73,728 字节以恢复跨窗口的标记或熵数据。原推荐输出组为一至两行，拷出后才交付给引擎。暂停可停在解码步骤或行之间。Stop 会清理正在使用或迟到的内核、解码器和私有缓冲。应用资源入口目前仍整幅读入编码文件。

编码源上限为 64 MiB，单边上限为 4,096 像素，每个模块最多 64 个流。原生分配总上限为 128 MiB，WASM 线性内存上限为 256 MiB。每个流最多推进 131,072 次。这些是资源与协作边界，单步耗时尚无墙钟保证。离线发布包括带哈希的模块、WASM、清单及 IJG 许可。JPEG 使用独立 ABI 1，IJG 库 ABI 为 62。

## 托管验收

构建作业使用固定 32 位 C 编码器制作测试输入，并将文件、生成命令及哈希作为独立产物保存。C 参考作业使用同一批输入，按原调用顺序加载。WASM 差分作业直接读取本批生成的内核，与 C 结果逐项比较尺寸、所有已定义目的字节、每个完成行与分组、错误阶段及数字码、警告次数及末次警告。失败前未写的目标字节以哨兵值检查。源读取日志可用于调查，逐次宿主读取时序不属于这项比较。

原版只在部分阶段的受保护代码中销毁解码器。C 参考先记录原生命周期，再回收残留分配。Web 端在各终止路径均要求关闭且分配归零。原始结果、未比较项和失败分别保留。缺项、未比较、前置作业跳过或比较失败均无法满足全套门禁。

验收涵盖基线和渐进扫描、采样比、灰度、直接 RGB、CMYK、YCCK、标记跨窗口、重启标记、输入短缺及收尾失败。真实 Session 使用源码与字节码验证主图、JPEG 遮罩、成品缓存隔离、数值消息、EOF 恢复、暂停和 Stop。浏览器通过真实 Worker、Layer 与 canvas 读回覆盖相同入口。[参考输入清单](../../tests/native/jpeg-cases.json) · [全套托管工作流](../../.github/workflows/test.yml)

共 43 项独立 C/WASM 差分，新增 20 个常规 Node 定义，其中 10 个测试内核及资源生命周期，10 个测试 Session。旧扩展名用例改用独立制作的 3×2 直接 RGB 控制图。三个分量固定为 32、96、160，原加载器写入的物理 BGRA 为 32、96、160、255，游戏读出的颜色值为 `0xa06020`。C 端检查全部六个像素，浏览器检查三种扩展名下的实际 Layer 与 canvas。

每个浏览器新增 8 个定义，覆盖 Asyncify、JSPI、源码和字节码。四个用于主图、遮罩及错误，另四个用于实际 Web 启动入口。精度用例用非恒定 4:2:0 图像确认三种设置的输出可以区分，在脚本改参并清除图像缓存后重新解码，核对整幅图与初始设置相符。该用例以同一内核直接解出的像素确认参数传递，编解码像素的独立依据来自上述 C 差分。浏览器的 JSPI 能力跳过单独计数。
