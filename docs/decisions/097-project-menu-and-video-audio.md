## 固定项目目录

固定 `SysInitImpl.cpp:935–1008` 选择项目容器或目录，随后在 `1098–1100` 设置当前目录；`StorageIntf.cpp:387–390` 对相对路径前置当前目录，`469–481` 保存媒体、域和路径。原静态 Storages 方法没有公开 currentPath／currentDirectory 属性，不新增不存在的脚本 API。

项目根必须在 Session 启动前确定，并与可执行目录区分。任意 `Scripts.execStorage` 或 `evalStorage` 都不能改变该根。归档／真实文件仍保持原导入位置和缓存身份；相对资源、自动路径、写入目标与公开绝对地址应在同一上下文解释。项目身份还必须进入持久存档与游戏库恢复，避免同一导入集合里的两个游戏共用存档。

本批接入选定项目上下文和对应启动／持久化链，既有 collection 记录保留原虚拟根身份作为明确的 Web 兼容入口。新文件夹导入默认按游戏目录识别；也可明确选择项目目录或包。原件、URL 和字节哈希保存在 `out/verification/storage/097-project-root/`。项目候选及其完整原 KAG 验收仍待托管执行。

公开 `/foo`、`\\foo` 以及省略媒体的当前域根地址从导入媒体根解析，不能误加项目目录；外部域与驱动器仍不属于导入媒体。导入文件名的边界继续严格要求相对路径。`-datapath` 先检查模板，再相对可执行目录归一化；处于子目录的程序可用 `../slots` 指向导入域内的父目录，越过导入根仍拒绝。System 公开前缀输出绝对 game 地址，写入器内部保存已绑定的规范键，防止二次加目录。

固定 `ConfMainFrameUnit.cpp:1539–1562` 在展开四个宏后调用 ExpandUNCFileName，直接支持 `$(exepath)/../slots`。没有宏的相对值在原进程使用 OS 当前目录；Web 以选定可执行目录代替这个宿主概念，是明确的环境映射。自动选择的 self-EXE 步骤需要宿主显式提供 executable；页面也可直接选择 `xxx.exe>` 项目根，始终只读包而不执行 EXE。

游戏库以实际选中的规范目录计算项目身份，不能按请求的不同大小写另算存档键；恢复时重新核对原始源身份和规范项目身份。启动入口独立于当前目录：库记录支持绝对媒体地址，合法的父目录入口在冻结项目上下文中验证后存为根地址，更新库设置也沿用原项目上下文。

尚有明确差异：导入器仍统一索引所有归档，低优先级但损坏的归档可能在项目选择前令导入失败。这里未吞掉原错误，也未宣称已经实现原生按访问打开归档的完整行为。优先级验收用有效但启动脚本会抛错的低优先包；惰性归档索引与访问时错误留在完整目标的后续范围。

## 视频音频的原版数值与读回

固定 `WaveImpl.cpp:515–568` 先把音量和平衡按整千单位截断，再查 101 项整数衰减表；中间值不是线性振幅。候选在真实媒体音频通路应用这一转换。IBasicAudio 用百分之一分贝表示衰减，因此 Web 振幅取 `10^(attenuation/2000)`，-10000 为静音；平衡只衰减一侧，另一侧保持全幅。[Microsoft 的接口定义](https://learn.microsoft.com/en-us/windows/win32/api/control/nf-control-ibasicaudio-put_volume)说明了单位与静音端点。

公开属性与实际图设置分开：固定 `dsmovie.cpp:747–762` 的 GetAudioVolume 存在无条件 return，调用方预置零衰减，所以公开 getter 为 100000，即使实际音频已衰减或静音。候选保留这个固定版本的行为，getter 不查询设备，也不会把真实播放增益重置。audioBalance 则用原反变换和整数截断读回。TJS 写入先经过原绑定的 signed int32 窄化，再施加控制范围；极大整数不能误按未窄化数值截到上限。

Node 定义用独立字面衰减控制点以及真实源码／编译字节码覆盖数值、读回、整千边界、32 位转换、无图写入和重开。浏览器验收观察实际左右声道及 AudioParam，音轨切换后必须保留实际控制，关闭重开使用新图默认值。原源与类继承哈希见 `out/verification/video-tracks/reference/097-native-audio-manifest.json`。这里是固定内置 DirectShow 路径的源码依据和 Web 音频实现，不宣称已执行原 KRKR2 二进制、覆盖所有设备错误或兼容未支持的 Flash 解码器。
