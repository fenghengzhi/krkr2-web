# WebGL 丢失、重建与会话暂停

浏览器失去 WebGL 上下文时，运行时保留 TJS VM、图层树、CPU 像素、资源和存档覆盖层，暂时停止脚本推进、计时器、转场及媒体播放。浏览器恢复上下文后，重新创建程序、uniform 位置与纹理；首帧提交成功后才解除图形暂停。用户主动暂停的游戏继续保持暂停。

此前 `WebGLRenderer.present()` 在发现上下文丢失时抛错，最终取消整个会话；未修改的静态图层也没有要求重绘的通道。现在显示故障通过渲染状态通知引擎，GPU 对象不再决定 VM 的生命周期。

## 模块边界

- `engine/ports/graphics.ts` 定义 `RendererStatus`、状态订阅及重试接口；这些契约不依赖 DOM。没有 GPU 生命周期的测试/其他渲染后端可以省略订阅。
- `backends/render/webgl2/program.ts` 创建程序与 uniform 位置，负责着色器和失败程序的清理。
- `backends/render/webgl2/renderer.ts` 处理上下文事件、GPU 状态恢复、纹理重新上传和首帧提交。
- `engine/session.ts` 合并用户暂停与图形暂停，冻结已有计时/转场/媒体服务，保留脚本与存档；恢复通知要求重新提交画面。
- 页面通过现有会话快照显示等待/失败状态，提供“保持暂停”和“重试显示”。Session 协议为 **4**，增加图形状态、用户暂停意图与 `retryGraphics()`；TJS WASM 的 ABI 仍为 1。

## 状态与资源所有权

| 渲染状态    | 引擎处理                                                               |
| ----------- | ---------------------------------------------------------------------- |
| `ready`     | 按用户暂停意图运行；一般图层按 revision 复用纹理                       |
| `lost`      | 暂停脚本、计时器、转场和媒体，等待浏览器恢复；不提交 GPU 绘图          |
| `restoring` | 程序已重建，仍保持图形暂停；从 CPU 状态重新合成并上传首帧              |
| `failed`    | 保留会话、待写数据和暂停状态，显示具体错误；用户可重试显示、备份或停止 |

监听器绑定在会话 Worker 拥有的 OffscreenCanvas 上。`webglcontextlost` 调用 `preventDefault()`，使浏览器可以恢复该上下文。丢失时清空纹理和程序引用；以前的 GPU 对象及 uniform 位置不能继续使用。该要求来自 [WebGL 上下文丢失/恢复规范](https://registry.khronos.org/webgl/specs/latest/1.0/#5.15.2)。

恢复重建程序及所有相关绘图状态，包括 framebuffer、纹理单元、混合、像素上传和写通道；原有 CPU 位图与合成缓存不需要重新读取游戏资源。纹理表从空表开始，所以即使图层 revision 没变化，也会重新上传。无效绘图、程序/纹理分配失败和构建中途再次丢失会进入明确状态，不把失败的帧标为完成。

`present()` 返回 false 表示未提交，Engine 保留 dirty 标志。即使游戏没有计时器、没有输入，或已被用户暂停，恢复事件也会使画面重新提交。只有资源重建与绘图检查都成功，才发布新的 ready generation；这表示首帧已提交，不保证浏览器合成器在同一时刻完成屏幕扫描。

构造阶段或纹理上传中途发生丢失也走相同路径。初次启动可以等待恢复后继续原来的启动调用；不重新执行已经完成的脚本，也不新建另一个 VM。显示重试只重建显示资源，不重新导入游戏或覆盖存档。

## 暂停、媒体与停止

`userPaused` 和图形状态是独立条件。任一条件要求暂停时，会话保持 paused；用户在等待恢复时选择“保持暂停”，恢复后仍需手动继续。用户取消自己的暂停也不能越过尚未恢复的图形状态。

沿用现有执行控制，在可挂起点阻止 VM 继续；已开始的 I/O 可以完成并等待继续执行。输入不进入暂停中的脚本队列，宿主的物理按键状态更新继续可用。Timer 保留剩余期限，转场补偿暂停时长；不会因恢复而补执行整段中断时间的定时回调。`System.getTickCount()` 仍是原有宿主单调时钟，本次不改变该脚本 API 的语义。

Wave/MIDI 混音和 VideoOverlay 收到 `pauseAll`，暂停播放位置与媒体回调。视频仍受浏览器原有解码与自动播放策略约束，恢复不绕过用户激活要求。

专项测试另发现：AudioWorklet 的电平报告原本以混音器播放帧数驱动，暂停后不再上报零输出，界面会保留旧电平。现在统计频率使用实际处理的输出块计数，播放时钟仍保持冻结。独立 Worklet 测试直接检查左右声道零输出、统计持续更新及播放位置不变；浏览器测试同时检查实际 Worklet 声部位置与视频时间。

停止先取消 VM 等待并解除引擎的状态订阅，迟到的恢复通知不会重新启动已停止的会话。Renderer.dispose 移除 Canvas 监听器、清理程序/纹理，并在上下文仍有效时主动释放它；重复 dispose 不再操作 GPU。既有存档提交失败保留待写字节的规则继续适用。

## 验证与限制

集成测试使用真实 Asyncify TJS VM，验证暂停意图、静态画面重绘、计时期限、自动转场完成顺序、启动等待、取消及迟到通知。浏览器测试在 Chromium、Firefox、WebKit 的 Asyncify/JSPI 路径上，使用 [WEBGL_lose_context](https://registry.khronos.org/webgl/extensions/WEBGL_lose_context/) 扩展触发实际上下文失效和恢复；没有用单纯派发 DOM 事件代替 GPU 资源失效。

测试中的 Worker 插桩只进入带唯一查询参数的测试 URL，用于保存扩展引用、观察重建/上传、以及让一次程序或纹理分配失败。扩展对象在丢失前获取并保留；上下文丢失时重新调用 getExtension 可能返回 null。生产 Worker 不提供故障注入命令。

画面校验涵盖普通纹理、透明度和隔离子树，比较恢复前后的实际浏览器像素；另覆盖重复丢失、初始构造丢失、纹理上传中断、失败重试、存档备份、用户暂停、停止后新会话，以及声音/视频续播。失败状态的窄屏布局也有检查。

这些结果证明所测浏览器的标准恢复事件路径，不证明每种实体 GPU/驱动故障都能恢复。浏览器若不能重新提供上下文，会话保持可停止和可备份的等待状态；重试按钮用于有效上下文上的资源重建失败，不使用测试扩展强制恢复真实硬件故障。没有在此阶段进行物理 GPU 重置、长期显存压力或整机性能测量。

后台/前台策略、完整输入与窗口 API、流式媒体、精确字体和其余引擎接口仍按 [非插件进度](../non-plugin-progress.md) 继续实现。

本阶段完整 `npm run check` 通过 216 项行为/集成测试与 386 项浏览器测试（294 常规 + 57 游戏库 + 35 PWA）。新增 6 项图形生命周期集成、1 项实际 Worklet 处理器测试及 48 项 GPU/媒体浏览器案例。`out/verification/graphics/check.log` 保存完整日志，`out/verification/graphics-matrix.json` 绑定当前源码、测试、配置、构建、WASM 和截图；此前的 PWA/游戏库/HTTP/ZIP 矩阵保留各自阶段证据。
