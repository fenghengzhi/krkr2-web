# 第 136 批原版存档、动态剧情加载与影片提示点

## 在桌面与浏览器之间转移进度

载入对应游戏，在“存档与备份”中选择“原版游戏存档”。暂停后可以多选原版文件，或选择整个存档目录。也可以导入一个 ZIP，包内路径从游戏存档目录开始。例如存档目录里有 `Slot.bmp` 和 `profiles/2.ksd`，ZIP 中就使用这两个名字。导入成功后通过游戏自己的读档菜单恢复进度。游戏若只在启动时读取设置或扫描槽位，可重新启动后再读档。

导入以该游戏当前的 `System.dataPath` 为根。目录选择会去掉最外层的目录名，保留内部的文件名和子目录。已有同名槽位会更新，一起导入的文件通过同一个 IndexedDB 事务写入。存储空间不足或读取失败时，原槽位仍可使用。游戏在事务期间写入的更新有优先权。[存档事务](../../src/engine/storage/save-overlay.ts)

导出的 `savedata.zip` 含浏览器在该存档目录中写入或导入的文件。将其解压到桌面版相应游戏的存档目录即可。ZIP 使用 UTF-8 文件名，缩略图、附加在图尾的书签、压缩文本和二进制文件均保留原字节。原版格式按目录相对路径迁移，适用于相同游戏的对应版本。默认 JSON 备份仍保存整份写入记录，并校验游戏标识。导入的存档总量上限为 64 MiB、文件数上限为 10,000。[转换与校验](../../src/player/native-saves.ts)

浏览器验收使用原 KAG 模板及原版 SDK 生成的书签，检查游戏内保存、导出、覆盖、重新导入与刷新后的读档。反向验收把同一提交的源码与字节码会话各自生成的 ZIP 交给 Windows 托管作业。桌面工具解压后，固定版本的原版 KRKR2 读取两个缩略图像素，恢复仍在调用中的宏参数、返回位置并继续剧情。两份 ZIP 的提交标识、摘要和原版执行日志都随作业归档。[浏览器迁移场景](../../tests/browser/native-saves.spec.ts) · [原版读回](../../tests/probes/native-save-transfer.ts)

## 动态剧情与影片提示点

游戏可以在 `onScenarioLoad` 中临时解析另一段剧情，再返回真正要播放的文本。原版安装新场景后会再次复位读取位置和条件状态，将活动宏退回本次调用的起点。Web 现在也在 `onScenarioLoaded` 执行前完成这一步，防止辅助剧本的宏参数或未结束的条件带入新章节。另有三份使用原 KAG 模板的验收剧本去掉了多余的行尾反斜杠。模板启用 `ignoreCR` 时会将该字符显示在历史记录里。[解析器](../../src/engine/kag/parser.ts) · [实际章节切换](../../tests/browser/kag-rewind.spec.ts)

游戏使用 `VideoOverlay.setPeriodEvent` 指定触发剧情回调的影片帧。新实现分别处理重新设置提示帧、按帧定位、按毫秒定位、倒带、回环及重新打开影片。例如已经触发的提示点，在按毫秒向前跳回时仍记为已触发。按帧移回到提示帧可以让它再次触发。验收以真实影片的后续帧作为观察边界，并核对按钮触发后的画面。[提示点状态](../../src/engine/media/video-period.ts) · [实际影片验收](../../tests/browser/video-period.spec.ts)

## 已取回的结果

第 132 批中，原版介绍游戏在 Chromium、Firefox 和 WebKit 的两种运行后端上全部完成了菜单、存读档、刷新恢复、返回和退出。三浏览器的独立兼容清单也已通过 96/96。回收时这一批仍在运行，已取得的常规浏览器结果为 2,385 项通过、44 项失败、2 项跳过。Firefox 第二分片的作业已成功，但归档当时无法下载，另两个第四分片尚未完成。Node 已报告 4,023 项通过、11 项失败和 2 项超时取消。[第 132 批运行](https://github.com/fenghengzhi/krkr2-web/actions/runs/45757288264)

本次列出的 49 份历史产物有 48 份按大小和 SHA-256 完成校验。第 133 批两版及第 134、135 批在取回时均为排队状态。第 136 批新增 17 个 Node 用例，每个常规浏览器项目新增 12 个用例，并增加一个原版 Windows 存档读回作业。原版 KAG 解析器对照增至 74 个场景。会话协议为 49，本批新增功能的验证结果留待下一轮取回。
