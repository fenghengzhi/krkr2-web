# 037 — VM 执行栈与临时寄存器

函数、try 保护体、超类委派和宿主返回的嵌套执行共用 256 层执行预算；函数和委派另各限制 128 层，为 Asyncify 的宿主调用栈保留异常处理空间。寄存器、展开参数、堆上的参数指针及收集到可变参数数组中的值共用 16 MiB 临时载荷预算；单次调用另限制一百万个参数。检查在分配和进入下一层之前进行，作用域退出时返还额度。预算错误可由正常 TJS catch 处理，外层 VM 可继续执行。

另检查 Emscripten 数据栈，保留 64 KiB 余量用于异常展开。数据栈位于线性内存，浏览器维护的可信调用栈与它不同，因此不能只用数据栈剩余字节代替逻辑深度边界。相关 API 见 [Emscripten stack.h](https://emscripten.org/docs/api_reference/stack.h.html)。这些默认值需要云端三浏览器双后端验证；本文件编写时新实现尚未验证。

寄存器池扩容先分配完整的新数组和索引，再发布使用计数，失败保留旧状态；压缩时按元素索引恢复 Current。每帧退出时显式清空寄存器，再返还池空间，异常和取消不再把已退出帧的局部值留到下次复用。清理保持当前帧登记，以允许终结回调重入；清理中的次要异常不会替换原始执行异常。其他隐式终结器抛出时的对象生命周期仍须继续审计。

参数准备改用作用域所有权和先计数后分配，兼容省略、普通、数组展开和匿名参数转发。空对象的数组展开返回正常脚本错误；数组拷贝限制在实际元素范围内。阶段 9、10 分别标识帧准备和参数准备，沿用现有时间片控制。

停止请求使用单独的原生取消异常，沿已有 silent 路径穿过 TJS try/catch，在最外层桥转换为 AbortError。宿主 Promise 的取消拒绝先转换回原生取消，以便 C++ 作用域清理完整执行。普通脚本异常和资源预算错误仍可捕获；测试检查原生返回状态，不能只凭 JavaScript 最外层 AbortError 推断脚本没有吞掉取消。

这些额度约束活跃执行及临时载荷，不是整个引擎堆占用的精确上限；缓存容量、普通游戏对象、编译器递归、隐式终结回调、原生库调用和此前未定位的 WebKit 异常仍需独立工作。完整非插件目标保持进行中。所有验证仅使用 GitHub-hosted Actions。

首轮 Tests `34853858703` 构建通过，Node 为 394/396，直接运行时六组合均未通过：Node/Chromium Asyncify 先触发宿主 `RangeError`，说明单独的 256 层计数不能保证足够余量；当前工具链明确不支持 Asyncify 与原生 WASM EH 混用，不能用切换异常编译模式绕过限制。其余组合的新增 try 夹具把块内变量当作全局变量读取；夹具现在在外层声明结果变量。原深层函数/try 挂起、继续和不可吞掉的取消检查已通过。

分配运行 `34854635620` 的旧字节码故障用例通过，但新执行诊断失败。寄存器池扩容与展开缓冲区失败已经回收，可变参数第一次使用 `TJSCreateArrayObject` 会延迟构造独立的 Array 原生类，在其部分成员注册失败时泄漏方法和调试记录。注册入口改用作用域所有权，原生类构造回滚不再依赖分配新的清理列表，基类析构也清理未完成派生构造的调试登记。上述修复仍待下一轮云端验证。

原决策 036 曾把临时实例保留归因为自身闭包。继续检查发现对象存储已对 `ObjThis == this` 调整引用计数，退出表达式后尚未清空的寄存器才是需要验证的持有来源。本轮增加不显式 invalidate 的临时实例/终结回调用例，分别覆盖源码、字节码和调试开关；在取得证据前不把原假设当作已确定根因。
