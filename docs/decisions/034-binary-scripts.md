# 二进制脚本资源与加载校验

Scripts、启动入口和直接运行时现可识别 `KBAD100\0` 序列化数据，返回原生 TJS Array/Dictionary 或标量。字节码和序列化数据按各自格式加载，文件、归档、网络、编码和存档仍由 TypeScript 管理。新增实现已推送，云端验证进行中；本页不代表整体非插件兼容完成。

## 资源与偏移

`Scripts.execStorage/evalStorage` 对二进制数据保留原生返回值；不将对象改造成 TJS 源码字符串。原生 `saveStruct(...,"b")` 的输出可由 Scripts 回读，也可随浏览器存档备份保存。

读取模式的 `o数字` 在识别二进制头之前生效，因此可以读取资源前缀之后的字节码和 KBAD 数据。原生 Array/Dictionary 的二进制流读取也使用该偏移。文本仍经过已有编码与压缩文本处理；明确的偏移越界会报错。

## KBAD 结构

沿用原生格式的 UTF-16LE 字符串、little-endian 数值、整数/浮点/void/null、短数组/字典、较长集合和 octet 标记。不是通用 MessagePack：TJS 的布尔、字符串和 octet 标记不同。读取负数 fix integer 时按有符号 8 位解释；空字典键按空字符串处理。修复了原读取器对此二者的不正确处理。

创建对象前先检查完整的单个值结构，包含每个长度、字典字符串键、嵌套深度和节点预算。保持原生“读取一个值”的尾部语义，允许后面还有文件数据。读取和临时字符串/集合用自动所有权清理；阶段 5 检查点允许验证及反序列化暂停、恢复和取消。原生 `loadStruct` 仍会在读之前清空其接收对象，不增加额外事务语义。

输入预算为 64 MiB、嵌套深度 256、单次值结构最多 1,000,000 个节点。字节数先与实际剩余空间比较，再计算地址与乘积，避免声明长度绕回后越界。

## 字节码结构

所有原生字节码入口先经过同一检查器，再进入原有加载器。检查文件版本与实际长度、DATA/OBJS/对象区块的闭合位置、各常量表长度、调试表、代码与数据长度、上下文索引及父链。对象/常量索引遵循格式的有符号 16 位范围。

指令检查区分寄存器、常量、直接属性名称、变长参数及跳转操作数；跳转和 superclass 入口必须落在完整指令边界。对象的寄存器范围由原生栈布局、参数和局部变量元数据决定；普通指令不能从代码末端继续取指。VM 本身也在取指前检查动态返回后的指针，避免 try 返回到代码尾部时直接解引用。

加载后的字符串常量使用保存的 UTF-16 长度，包括 NUL 与孤立代理项。名称的原生显示规则继续沿用 TJS。

## 验证范围与后续

新增独立编码器覆盖原生写出器较少产生的数值/长度编码，另通过原生 `saveStruct` 回读检查实际互通。验证包括截断、超大声明长度、非法上下文/寄存器/常量/跳转、指令尾部、嵌套 try、转发与展开参数、浏览器存档和阶段 5 暂停取消。

首轮 [34832886756](https://github.com/fenghengzhi/krkr2-web/actions/runs/34832886756) 在构建时发现新增校验器将全局错误消息常量写成 TJS 命名空间成员，编译失败，测试未执行。命名空间已修正；原构建日志按运行 ID 保留。

结构检查不等于完成所有 VM 指令语义和资源审计。原字节码对象构造失败时的所有权、深度调用/try 栈预算、加载阶段原生分配统计与部分同步复制仍待继续；不能据此宣称任意输入都可在固定时间内中止，或已证明所有原生分配不泄漏。完整路径、自动编码策略和其余非插件需求继续在总进度中保留。
