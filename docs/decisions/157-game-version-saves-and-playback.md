# 第 157 批跨版本读档、影片回调和文字度量

## 在更新后的游戏中继续进度

游戏更新、重新分卷或更换发行目录后，浏览器可能给它分配新的游戏身份。在新版游戏里暂停，打开“存档与备份”中的“从其他版本复制存档”，选择旧版和它的存档目录。复制完成后，继续游戏，从游戏自己的读档菜单打开进度。游戏库中移除旧版的资源后，浏览器里保留的存档仍可选择。新版游戏能读取哪些旧存档格式由游戏脚本决定。[玩家界面](../../src/app/save-transfer.ts)

来源列表按已有存档查找。新写入的存档会一起记录游戏标题和实际数据目录。较早的存档也可以使用，玩家可手动选择它的自定义目录。来源目录下的相对文件名和子目录会复制到目标游戏的 `System.dataPath`。默认保留目标中的同名文件，只有玩家勾选替换才覆盖。目标端在一次 IndexedDB 写事务内判定重名、检查路径和空间，并提交整批文件。来源存档保持原样。[浏览器持久化](../../src/backends/files/indexeddb-saves.ts) · [目标存档合并](../../src/engine/storage/save-overlay.ts)

游戏库验收用两份发行路径及数据目录不同的原版 KAG 游戏，分别保存剧情值 7 和 99，从新版选择旧版目录。默认复制后，新版的剧情值 99仍应保存在原槽位。勾选替换后，应能在新版游戏中读回旧版的剧情值 7。用例还从游戏库重开新版，检查嵌套文件、旧版原始字节及无目录元数据的 v1 存档。Node 验收另覆盖另一个会话刚写入的同名文件及复制失败。[游戏库验收](../../tests/library-browser/save-transfer.spec.ts) · [存档事务用例](../../tests/conformance/native-saves.test.ts)

## 遇到影片帧标记时的脚本顺序

图层影片先更新画面并运行游戏的 `onFrameUpdate`，回调返回后再根据当时的标记判断是否触发 `onPeriod`。游戏可以在当前帧取消标记、推迟到后面的帧，或关闭并打开另一段影片。同一回调里重新打开影片时，按对象当时的标记继续处理。播放器会丢弃延迟送达的旧影片帧。浏览器暂缓提供画面时，未占用帧回调的影片仍可按播放时钟触发标记。浏览器验收用双图层的像素与游戏脚本记录核对回调顺序。[影片控制](../../src/engine/media/videos.ts) · [逐帧浏览器验收](../../tests/browser/video-frame-cue.spec.ts)

## 空对白行的高度

原版图层的位图会记住最近测量的字符串、宽度和高度。首次查询空串高度为 0。测量过非空对白后再查询空串，会得到该字体的行高。Web 图层按位图管理这份状态，字体设置及预渲染字体映射发生变化时重新应用。依赖空行高度安排下一行对白或选择项的脚本会看到这些变化。验收覆盖空行第一次查询、有字对白之后的查询，以及字体修改后恢复原值这三种布局。[位图文字度量](../../src/engine/graphics/font-metrics.ts) · [对白布局验收](../../tests/browser/text-metric-cache.spec.ts)
