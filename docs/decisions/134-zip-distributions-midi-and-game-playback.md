# 第 134 批 ZIP 发行包、MIDI 音量和实际游戏播放

## 直接载入发行包

在“游戏位置”选择“自动识别游戏目录或 ZIP 发行包”，再导入单个 ZIP 或它的远程链接。播放器识别包内的 `content-data`、`data.xp3`、`data.exe` 或脚本目录。播放器也支持从单个自包含 EXE 读取嵌入的 XP3。一个发行包含多个独立游戏时，在“程序所在目录”填入所选游戏的包内目录。[目录选择](../../src/engine/storage/distribution.ts)

包内 XP3、补丁和散装资源使用游戏原来的相对路径。游戏库保存原 ZIP 及所选目录，刷新启动时恢复该选择和同一份存档。此前保存的库条目仍使用原存档标识。现有验收用原 KAG 模板及补丁剧情，保存书签、保存游戏库、刷新，再从库中启动并读回剧情。[库恢复验收](../../tests/library-browser/kag-distribution.spec.ts)

ZIP 的 deflate 成员可按范围读取，超过 64 MiB 的音乐无需分配整个解压文件。首次读取仍要完整解压并检查声明长度和 CRC，校验通过才返回请求的字节。首播等待时间取决于完整成员的大小。外层 ZIP 和内部 XP3 使用独立解压池，停止时释放两者。共享缓存与前向游标有固定上限，回跳可能重新解压。[范围读取](../../src/formats/binary/deflate-ranges.ts) · [ZIP 接线](../../src/formats/zip/archive.ts)

音乐验收使用含 72 MiB PCM 的单成员 WAVE，起点、远端和回跳处有不同的音调与声级。Node 逐采样比较独立原始 PCM，浏览器采集真实 AudioWorklet 输出并核对频谱、声级和 SLI 标签。源码与字节码入口均覆盖。[游戏音乐验收](../../tests/browser/distribution-music.spec.ts)

## MIDI 音量与游戏画面

`MIDISoundBuffer.volume` 和 `volume2` 先按原版整数步骤合成为 7 位音量，再作用于文件内的通道音量。例如通道值 100 在半音量时变为 49。较小音量可以真正归零。淡出、暂停、重开文件和恢复音量沿用同一规则，直接通过 `midiOut` 播放的音符使用独立音量。文件中某个通道的首个音符会重新应用该通道记住的音量。[音量实现](../../src/engine/media/midi-volume.ts) · [真实按钮与声音验收](../../tests/browser/midi-volume.spec.ts)

独立参考 MIDI 文件直接写入预期的通道值，Web 比较完整 PCM。Windows 原版 SDK 的新增观察覆盖公有音量属性的整数转换和范围。原设备的声音和 CC7 输出仍待实测。

131 的截图测试将加速显示的 128 当作保存位图的颜色。固定原版整数合成路径应得到 126，本批保留屏幕、遮罩和转场检查，改为逐项读取保存前后的 RGB／遮罩，并增加同场景的原版 BMP 往返对照。字体测试也会保留实际栅格边界错误及原始像素，以便定位首个失败断言。[场景验收](../../tests/browser/scene.spec.ts) · [共享原版图层对照](../../tests/helpers/layer-alpha-rows.ts)

介绍游戏的只读状态和排版观察合并为一次查询，避免诊断操作移动真实鼠标或消耗多次交互往返。路线链接、翻页、菜单存读档和确认按钮仍使用实际点击。KAG 菜单图层保存通过原字典类方法调用，保留原场景和层次断言。
