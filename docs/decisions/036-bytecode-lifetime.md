# 036 — 字节码加载的所有权与失败回滚

字节码加载按验证、常量池、上下文构造、链接四步进行。加载器保留每个新对象的初始引用，直到所有链接安装完成；成功后释放这些初始引用，失败或取消时先失效所有尚未发布的上下文，再释放引用。上下文只在构造成功后登记到脚本块，并用保存的列表位置移除，避免大量上下文回收时反复扫描列表。

常量池、代码、变体、调试位置和名字使用作用域所有权。字符串池扩容先分配完整的新存储，再替换旧索引。源码构造路径共用的缓冲区扩容也只在分配成功后替换指针。超类 getter 和属性 getter/setter 持有一致的引用。

验证器拒绝从顶层不可达的上下文和强引用环，并按常量、名字、上下文及符号记录收取 128 MiB 的构造预算。这个保守预算用于限制小输入展开成大量原生结构的情况，不代表任意时刻堆占用的精确上界，也不代替分配失败处理。

阶段 6、7、8 分别在常量池、上下文构造和链接循环中使用现有的时间片检查。暂停时保留局部所有权，取消时正常展开原生异常并清理。只读诊断出口报告原生分配字节、字符串单元、脚本块和上下文数量；WASM 线性内存长度不用于证明活跃分配已释放。[Emscripten 内存诊断文档](https://emscripten.org/docs/porting/Debugging.html) 描述了 `mallinfo()` 的用途。

独立分配故障构建由 `KRKR_TEST_ALLOCATOR=1` 启用，使用独立构建目录和源身份；清单明确标为诊断内核。正式构建默认关闭，不能将诊断内核当作发布验证证据。

验证仅在 GitHub-hosted Actions 运行。本轮的新生命周期用例和故障诊断尚未取得完成结果；旧二进制脚本基线仍保存在决策 034、035 和历史报告中。VM 调用/try 栈预算、其他原生分配路径和历史 KAG 异常仍是后续工作，不能据此声明非插件部分全部完成。

首轮 `34846307441` 的 Node 结果为 388/391，取消三个阶段均通过，但继承文件被拒绝，两条恢复用例保留了方法上下文。原生编译器为 superclass proxy 写入 `RET; NOP` 尾部，验证器此前将这个哨兵误认为可执行 fallthrough；现在只允许该上下文的这个特定尾部，并禁止跳转到哨兵。另一个现象来自实例成员闭包的自身引用：生命周期用例现在在验证方法结果后显式 `invalidate` 实例，再删除全局绑定。自动循环回收仍是独立未完成项，不能把显式清理的通过等同于自动回收。原失败完整保留。
